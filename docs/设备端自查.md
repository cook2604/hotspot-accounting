# 热点分账 · 设备端自查

这个 APP 依赖内核里的流量计数器，而不同红米/小米机型的**内核能力差异很大**。
装 APK 之前，先用下面任意一种方式跑一遍自查，就能提前知道你的手机是否满足条件，
以及万一统计不到流量时该改哪里。

---

## 一、最快的方式：让 APP 自己查

装好 APK 后打开，进入 **设置 → 运行计数自检**：

- 如果提示「计数正常」→ 一切就绪。
- 如果提示「计数未增长」→ 看下面的诊断表。
- 设置页还会直接列出 `tc` / `ebtables` / `ifb` 是否可用，以及识别到的热点接口名。

APP 内部就是执行下面的命令，所以你也可以手动跑一遍来交叉验证。

---

## 二、手动自查（终端 / adb root）

用 KernelSU 或 APatch 的终端，或者 `adb shell` 然后 `su`，执行：

### 1. 有没有 nft，内核支不支持 bridge 表

```sh
nft --version

# 关键测试：能否创建 bridge family 的表
nft add table bridge hsacc_test
nft add chain bridge hsacc_test c '{ type filter hook prerouting priority -300; policy accept; }'
nft list table bridge hsacc_test
nft delete table bridge hsacc_test
```

- **四条都成功** → 你的内核支持本 APP 的首选方案（按 MAC、二层计数，最准）。
- 报 `No such file or directory` 或 `Operation not supported` → 内核没开 `CONFIG_NF_TABLES_BRIDGE`，
  APP 会自动退回到 iptables 方案。

### 2. 热点接口叫什么名字

```sh
ip -o link show
```

常见结果：

| 接口名 | 含义 |
|---|---|
| `ap0` / `ap1` | 高通/联发科平台的热点接口，最常见 |
| `swlan0` | 部分小米机型 |
| `softap0` | 部分厂商 |
| `wlan1` | 单射频机型的热点接口 |
| `wlan0` | 在单射频机型上，热点就是 wlan0 本身 |

如果热点开着却看不到 `ap*`，把 `ip -o link show` 的完整输出发我，我按你的机型调整识别前缀。

### 3. 客户端到底在不在邻居表里

先让一台设备连上热点并刷一下网页，然后：

```sh
ip -4 neigh show
ip -6 neigh show
```

你应该能看到类似：

```
192.168.43.123 dev ap0 lladdr 3c:5a:37:aa:bb:cc REACHABLE
```

- **看得到** → 设备发现没问题。
- **看不到** → 说明客户端不在这个网络命名空间里（少数机型热点跑在独立 netns）。
  可以用这条命令确认：

  ```sh
  ls -l /proc/*/ns/net | head
  ip netns list
  ```

### 4. DHCP 租约文件在哪（用来拿设备主机名）

```sh
ls -l /data/misc/dhcp/
cat /data/misc/dhcp/dnsmasq.leases 2>/dev/null
```

有些 ROM 会把它放在别处，这几个路径 APP 都会尝试：

```
/data/misc/dhcp/dnsmasq.leases
/data/vendor/dhcp/dnsmasq.leases
/data/misc/dhcp/dhcpd.leases
/cache/dhcp/dnsmasq.leases
```

拿不到租约文件**不影响流量统计**，只是设备名显示不出来，需要你手动备注。

### 5. 限速 / 断网相关能力

```sh
which tc ebtables iptables nft
tc qdisc show                      # 看看系统在热点接口上已经挂了什么队列
ls /sys/module/ifb                 # 有没有 ifb 模块（上下行限速要用）

# 断网能力：nftables 的 bridge family 能否建表建链（按 MAC 拦截的前提）
nft add table bridge hsacc_probe
nft add chain bridge hsacc_probe c '{ type filter hook prerouting priority -250; policy accept; }'
nft list table bridge hsacc_probe
nft delete table bridge hsacc_probe
```

**断网会按这个顺序自动选机制**，前两者都按 MAC 拦截，不受客户端换 IP 影响：

| 顺序 | 条件 | 效果 |
|---|---|---|
| 1 | 上面三条 nft 命令都成功 | **nftables bridge，按 MAC**（推荐） |
| 2 | `which ebtables` 有输出 | ebtables，按 MAC（语义等价） |
| 3 | 只有 iptables | **按 IP，续租换 IP 后失效**（界面会明确标注成「按 IP」） |

> **不需要 ebtables 也能按 MAC 断网。** nftables 的 bridge family 同样可以，
> 而且和计数用的是同一个 family —— 既然计数能用，断网就一定能用。
> 界面「设置 → 网络控制能力 → 断网方式」会显示实际选中的是哪一个。

> ⚠️ **重要**：Android 的热点自己会在接口上挂 HTB 队列。
> 如果你的 `tc qdisc show` 显示接口上已经有 `htb`，APP 的限速会**主动拒绝执行**并提示你，
> 而不是硬叠上去 —— 硬叠会打断整个热点。断网功能不受此影响。

### 6. USB 共享（给台式机 / 笔记本供网）

先开启：**设置 → 连接与共享 → USB 共享网络**（或下拉通知栏里找到「USB 共享」）。
开启后执行：

```sh
ip -o link show | grep -Ei 'rndis|usb|ncm'
ip -4 addr show | grep -A2 -Ei 'rndis|usb|ncm'
ip -4 neigh show
```

你应该能看到类似：

```
7: rndis0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
    inet 192.168.42.129/24 ...
192.168.42.130 dev rndis0 lladdr 8c:16:45:aa:bb:cc REACHABLE
```

**这三点决定了 USB 能否被统计：**

| 检查 | 期望结果 | 说明 |
|---|---|---|
| 接口名 | `rndis0` / `usb0` / `ncm0` 之一 | 这三种前缀 APP 都已覆盖 |
| 邻居表里能看到电脑 | 有 `dev rndis0` 的行 | 看不到就统计不到，把输出发我 |
| 网桥是否包含该接口 | 见下方命令 | 决定二层计数能否生效 |

确认接口是否在网桥里（USB 计数依赖这一点）：

```sh
ls /sys/class/net/rndis0/brport 2>/dev/null && echo "在网桥中" || echo "不在网桥中"
ls /sys/class/net/br0/brif 2>/dev/null
```

- **在网桥中** → APP 的二层计数直接生效，无需任何额外配置。
- **不在网桥中** → 说明该机型对 USB 共享走了独立转发路径。请把上面命令的输出发我，
  我按你的内核调整计数方式（可退回 iptables 后端）。

**限速说明**：同时开着 Wi-Fi 热点和 USB 共享时，APP 会为每台设备分别解析它所在的接口，
把限速规则下发到正确的那个接口上，不会互相干扰。

## 三、诊断对照表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| APP 提示「未获得 root 权限」 | KernelSU 还没给本 APP 授权 | 打开 KernelSU，在「超级用户」里给「热点分账」授权 |
| 设备列表一直空 | 客户端不在同一 netns，或接口前缀没被识别 | 跑上面第 3 步，把输出发我 |
| 设备能列出但流量一直是 0 | 规则没被走到（厂商规则提前放行） | 跑自检，把诊断信息发我；或手动 `nft list chain bridge hsacc prerouting` 看计数器 |
| 只有上传有数、下载为 0 | 下行规则没装成功 | 手动 `nft list chain bridge hsacc prerouting`，应看到 `ether daddr <mac>` 规则 |
| 重启热点后流量从 0 开始 | 正常，规则随热点重建 | 无需处理；历史用量已落库，不会丢 |
| 同一台手机出现两条记录 | 手机开了「随机 MAC」 | 在实时页给它备注命名，两条记录分别计费即可 |
| 限速报「已存在系统自建的队列规则」 | 与 tethering 的 HTB 冲突 | 先关热点再开热点，然后重试；或只用断网功能 |
| USB 共享的电脑不出现 | 接口名不在识别范围内，或不在网桥中 | 跑上面第 6 步，把输出发我 |
| USB 设备出现了但限速无效 | 该机型 USB 分享走独立转发路径 | 把第 6 步的网桥检查结果发我 |
| 实时页显示「未知」接入方式 | 邻居表缺 `dev` 字段 | 不影响计费；只是标签显示不出来 |
| 限速报「无法确定该设备所在的网络接口」 | 同时开了多个共享方式且邻居表查不到该 IP | 确认设备仍在线；必要时重新连接一次 |

## 四、把结果发我

如果自检没通过，请把这几条的输出贴给我，我按你的实际内核改代码：

```sh
nft --version
nft add table bridge hsacc_probe && echo BRIDGE_OK || echo BRIDGE_FAIL
nft delete table bridge hsacc_probe 2>/dev/null
ip -o link show
ip -4 neigh show
ip -6 neigh show
ls -l /data/misc/dhcp/ 2>/dev/null
which nft iptables ebtables tc
getprop ro.build.version.release
getprop ro.product.model
uname -r

# —— USB / 多方式共享相关（要统计 USB 时加上这几条）——
ip -o link show | grep -Ei 'rndis|usb|ncm|bt-pan'
for i in $(ls /sys/class/net); do
  [ -e /sys/class/net/$i/brport ] && echo "$i 在网桥中"
done
ls /sys/class/net/*/brif 2>/dev/null
```
